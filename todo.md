# Лампа тональностей — архитектура проекта

Обновлено: 22.10.2026

## Цель и исследовательский вопрос

Лампа-цилиндр слушает живую музыку и показывает тональность цветом, а ноты и атаки — световыми волнами. Лампа — витрина; ядро проекта — измерения того, как анализ музыки в реальном времени работает в реальных условиях.

**Рабочий вопрос:** насколько ошибки распознавания в живой комнате и на бытовом железе влияют на определение тональности, и каким компромиссом между задержкой и стабильностью это достигается?

**Для кого:** Institute of Computational Perception JKU. Проект продолжает их работу по транскрипции фортепиано в реальном времени (Hu, Peter, Schlüter, Widmer, ISMIR 2025), где замеры на разном железе и записи в комнате названы будущей работой.

**Чего не утверждаем:** научной новизны алгоритмов. Ценность — в аккуратной интеграции, воспроизводимой оценке и наглядном демо.

## Архитектура

Три независимых слоя анализа сходятся в одну функцию отрисовки кадра; каждый слой работает на своём временном масштабе.

```
 Входы                     Слои анализа                       Выход

 Микрофон ──┐        ┌─▶ Хрома → тональность ──── фон ──┐
 (Shure +   │        │   (любая музыка, медленно)        │
 Behringer) │        │                                   │
            ├────────┼─▶ Онсеты по полосам ───── волны ──┼─▶ Отрисовка кадра ──DDP──▶ Лампа
 MIDI ──────┤        │   (любая музыка, быстро)          │   (ноутбук, Python)        (ESP32, WLED)
            │        │                                   │
 Файлы ─────┘        └─▶ Транскрипция → ноты ──── ноты ──┘
 (MAESTRO,               (фортепиано и MIDI)
 ASAP, синтез)
```

Модели внутри каждого слоя сменные: один интерфейс, свой адаптер и отдельный процесс на модель.

- **Хрома → тональность** — фон лампы. Работает на любой музыке, включая оркестр: хрома меряет распределение звучания по 12 классам и устойчива к ошибкам в отдельных нотах.
- **Онсеты по полосам → волны.** Спектр делится на 32 полосы по высоте лампы; резкий рост энергии в полосе (spectral flux) рождает волну на этой высоте. Транскрипция не нужна.
- **Транскрипция → ноты** — опционально, там, где она надёжна: фортепиано и MIDI. На оркестре и ансамбле не используется.

## Входы

Все входы приводятся к одному формату событий с метками времени по часам аудио, поэтому остальной конвейер не знает, откуда пришёл звук.

| Вход                             | Как                                                                                       | Зачем                                |
| -------------------------------- | ----------------------------------------------------------------------------------------- | ------------------------------------ |
| Микрофон                         | Shure (динамический) → Behringer USB → ноутбук; 48 кГц, пересэмплинг в 16 кГц для моделей | реальные условия «в комнате»         |
| MIDI                             | USB или DIN с пианино, `mido`                                                             | точные ноты; эталон для оценки       |
| Линейный выход цифрового пианино | второй вход Behringer                                                                     | чистый сигнал без комнаты            |
| Файлы                            | MAESTRO (аудио + MIDI), ASAP (тональности и модуляции), синтез FluidSynth                 | воспроизводимые тесты без пианино    |
| Re-amping                        | файл → колонки → комната → Shure                                                          | условие «комната» на записях MAESTRO |

**Проигрыватель:** скрипт подаёт WAV и MIDI в реальном времени, MIDI — в виртуальный порт; ведущие часы — часы аудио, поэтому рассинхрона нет.

**Выбор источника:** автоматически MIDI, если за последние ~10 с был MIDI-пакет, иначе микрофон; плюс ручной переключатель. Режим «оба сразу» пишет параллельные логи для оценки.

## Модели и методы

Каждая модель подключается через адаптер с общим интерфейсом и работает в своём процессе со своим venv; связь — ZeroMQ или Unix-сокет. Новая модель = один адаптер + строка в YAML-конфиге.

**Транскрайберы** (`Transcriber.process(block, t) → [NoteEvent]`)

| Модель                                  | Веса                 | Лицензия весов | Роль                                                |
| --------------------------------------- | -------------------- | -------------- | --------------------------------------------------- |
| MIDI passthrough                        | —                    | —              | эталон                                              |
| Классический DSP (FFT, пики, гармоники) | —                    | своя           | базовая линия, кандидат для ESP32                   |
| Basic Pitch (Spotify)                   | < 17 тыс. параметров | Apache 2.0     | лёгкая; работает и на гитаре                        |
| ByteDance High-Resolution               | ~172 МБ (есть ONNX)  | CC BY 4.0      | самая точная для фортепиано; оффлайн-эталон         |
| madmom (транскрипция)                   | десятки МБ, оценка   | CC BY-NC-SA    | модель института                                    |
| Causal-AMT (JKU)                        | кода пока нет        | —              | ~53 GFLOP на секунду звука; запросить код у авторов |

**Определители тональности** (`KeyEstimator.update(...) → (тональность, уверенность)`)

- Krumhansl–Kessler: корреляция 12 чисел с 24 профилями — формула, не ML.
- Temperley / Albrecht–Shanahan: тот же алгоритм, корпусные профили.
- Spiral Array, Chew (CEG): центр тяжести нот на спирали квинт.
- CNN из madmom (Korzeniowski & Widmer, 2018): по скользящему окну, отдаёт 24 вероятности.

Вход для первых трёх — хрома (librosa CQT или Deep Chroma из madmom), ноты транскрипции или MIDI.

**Фильтры поверх любого определителя** — свой код, не параметры модели:

- экспоненциальное затухание (постоянная времени 4–8 с вместо жёсткого окна 10–20 с);
- два окна: длинное ~12–15 с для стабильности, короткое ~3 с для быстрой реакции на модуляцию;
- HMM с прямым проходом (параметр `STAY`, переходы по квинтовому кругу), каденции как сильное свидетельство;
- раздельный выход: тоника и лад со своими уверенностями (для пустых квинт лад «не определён»).

**Онсеты и доли — без транскрипции**

- Онсет = «что-то началось и насколько резко», без высоты; аккорд считается одним событием.
- Spectral flux (сумма роста энергии спектра между кадрами) + пик-пикинг: порог над скользящим средним, не ближе ~30 мс к предыдущему. Готовые варианты: SuperFlux, онлайн-детектор madmom (RNN), `librosa.onset_strength`.
- Flux по каждой из 32 полос даёт и высоту волны, и локальную плотность; величина пика = сила удара (акцент).
- Работает на ESP32-S3, поэтому доступно в автономном режиме. Хуже на мягких атаках (струнные, хор), онсеты ближе ~20–30 мс сливаются.
- Доли: Beat This! (Foscarin, Schlüter, Widmer, 2024), лицензия MIT, есть ONNX — пульс лампы на доли, акцент на сильную.

## Визуализация

Вся лампа держит один оттенок — цвет тональности; события музыки показываются осветлением этого цвета (смесь с белым), а не сменой оттенка.

**Слои кадра, снизу вверх:**

1. **Фон — тональность.** Цвет по выбранной карте (Скрябин, Римский-Корсаков). Переход 1–2 с. Насыщенность = уверенность: при размытой тональности фон приглушается.
2. **Быстрый голос гармонии.** Фон смещается к цвету текущего аккорда на ±15–20° по оттенку — как быстрый голос света в «Прометее». Карта Скрябина идёт по квинтовому кругу, поэтому смещения к доминанте и субдоминанте малы и естественны.
3. **Напряжение.** Яркость/насыщенность фона от гармонического напряжения: тоника спокойна, доминанта и диссонанс ярче, разрешение — мягкий спад.
4. **Волны от оси.** Вертикальная ось внутри лампы — ось частот (басы внизу). Онсет на высоте `h` порождает сферическую волну: при `r = R` вспыхивает кольцо на высоте `h`, затем оно расщепляется на два, уходящих на высоты `h ± √(r² − R²)`, и гаснет. Перед вспышкой — слабое предсвечение; сила удара = яркость и скорость волны.

**Почему кольца:** кольцо горит по всей окружности, поэтому видно с любой стороны. Режимы «нота по углу» (спираль, хрома-эквалайзер) упираются в то, что зритель видит лишь переднюю половину цилиндра.

**Дополнительные режимы для сравнения:** водопад хромы (история гармонии уходит вверх), хрома-эквалайзер по квинтам с разворотом гаммы тональности к зрителю, A/B двух моделей на половинах лампы.

**Возможный физический вариант:** центральная LED-лента как реальная ось + полупрозрачная внешняя оболочка — вспышка на оси, через 50–100 мс волна на оболочке.

### Смена аккорда внутри тональности — сдвиг оттенка фона

`оттенок = оттенок_тональности + α · (оттенок_аккорда − оттенок_тональности)`, α ≈ 0,2–0,3, не больше ±15–20°, расчёт по кругу в OKLCH, переход 0,2–0,4 с.

|              | Смена аккорда      | Модуляция              |
| ------------ | ------------------ | ---------------------- |
| Величина     | ±15–20°            | полная смена цвета     |
| Длительность | пока звучит аккорд | до следующей модуляции |
| Скорость     | 0,2–0,4 с          | 1–2 с                  |

В квинтовой карте направление сдвига совпадает с функцией: T — без сдвига, D — на квинту в одну сторону, S — в другую, побочные доминанты дальше. Напряжение (D7, уменьшённые) — яркостью и белизной, не оттенком. Нужен определитель аккордов (Deep Chroma + шаблоны или CNN madmom); функция = правило из пары «аккорд + тональность». Слайдер силы α от 0 до ~0,3; альтернатива — цвет аккорда в верхних и нижних 2–3 кольцах.

### Быстрая игра: как избежать каши

1. Мягкое сложение волн: `tanh(сумма)` или максимум вместо суммы.
2. Адаптация к плотности онсетов (за ~0,5 с): короче жизнь, уже фронт, слабее каждая волна.
3. Группировка: аккорд (~50–80 мс) — одна волна; повтор в той же полосе раньше ~100 мс подсвечивает существующую волну; лимит 6–8 волн одновременно.
4. Пассаж (монотонная последовательность онсетов по высоте) — бегущее пятно с хвостом вместо отдельных волн.
5. Волны только для акцентов (сила онсета выше соседних, сильная доля); остальное — тихое мерцание полосы.
6. При высокой плотности — переход от сферических волн к дисковым вспышкам.

### Режим «барабан»: квинтовый круг вокруг лампы

Вертикальные полосы по окружности — 12 тональностей по квинтовому кругу; к зрителю повёрнута текущая. С картой Скрябина барабан становится непрерывным спектром.

- **Модуляция = поворот** по кратчайшему пути (≤ 180°), 1–2 с: C → G — одна полоса (30°), C → F# — разворот.
- **Функция аккорда = покачивание** к доминанте или субдоминанте, быстрее и меньше поворота — «быстрый голос» движением, а не оттенком.
- **Волны от оси** осветляют кольца поверх полос.
- **Контекст:** по бокам видны соседние тональности.
- **Плавность:** цвет — непрерывная функция угла с интерполяцией между ключевыми цветами, поэтому 16 столбцов дают плавный поворот.

Решить: лицевая сторона (метка на корпусе или выбор в приложении); задняя половина у стены не важна, в центре комнаты — приглушать; минор — полоса параллельного мажора темнее или второй ярус (низ — мажор, верх — минор); скорость покачивания, чтобы барабан не «нервничал» на каждом такте.

Моно-режим (вся лампа в цвете тональности) — атмосфера; барабан — «карта гармонии», нагляднее для демо и тренировки слуха. Оба — разные функции отрисовки над одними данными.

## Железо

Лампа 16×32 (две матрицы 16×16 одна над другой) на ESP32 со стоковым WLED; считает ноутбук, кадры уходят по Wi-Fi в DDP. Orange Pi отложен.

**Вычисления:** ноутбук Ryzen 7 PRO 5850U (8 ядер, 15 Вт, 30 ГБ ОЗУ), только CPU. Замеры — от сети, профиль `performance`, 8 потоков.

**Связь:** кадр 512 × 3 = 1536 байт → два DDP-пакета (максимум 480 пикселей на пакет), 50–60 кадров/с. В WLED включить Disable WiFi sleep. Позже — USB от ноутбука или UART для финальных замеров задержки.

## Измерения

Итог — одна сводная таблица: модель × условие (чистая запись / линия / комната) × платформа → точность и задержка.

| Что               | Метрика                                                                                                | Как                                                                                                          |
| ----------------- | ------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------ |
| Ноты              | P / R / F1 по онсетам, допуск 50 и 100 мс; отдельно октавные ошибки; совпадение по хроме               | `mir_eval.transcription`, эталон — MIDI                                                                      |
| Тональность       | weighted score MIREX; доля времени с верной тональностью                                               | `mir_eval.key`, эталон — ASAP или MIDI + ручная разметка                                                     |
| Стабильность      | ложных смен цвета в минуту на пьесах без модуляций                                                     | логи оценщика                                                                                                |
| Реакция           | задержка обнаружения модуляции, с                                                                      | против эталонной смены тональности                                                                           |
| Вычисления        | real-time factor; время стадий: медиана, p95, p99; переполнения буфера; CPU и температура за 10–15 мин | `time.perf_counter()`, `psutil`                                                                              |
| Сквозная задержка | клавиша → свет, мс, по составляющим                                                                    | пьезо на пианино + фототранзистор на светодиоде в два канала записи; для первой оценки — съёмка 240 кадров/с |

**Калибровка:** медианное смещение MIDI ↔ звук по 20–30 отдельным нотам вычитается из всех замеров.

**Режим повтора:** записанные сессии прогоняются через потоковый конвейер блоками — все модели получают идентичный вход.

**Тестовые случаи:** гамма до мажор (накопление, конкуренция с ля минором), пустые квинты (лад не определён), модуляции C → G и C → F#, плотная фактура, гитара на Basic Pitch.

**Набор:** 10–20 фрагментов по 1–3 мин разных стилей; логи в JSONL/Parquet; любой результат пересчитывается одной командой.

## Этапы

Порядок построен так, чтобы каждый шаг давал работающий результат и не требовал покупок раньше времени.

1. **Скелет на ноутбуке:** микрофон → хрома librosa → Krumhansl + затухание → цвет на экране (pygame).
2. **madmom:** установка из GitHub без истории (~100–150 МБ трафика), проба KeyRecognition, CNNChordRecognition, PianoTranscriptor на своих записях.
3. **Адаптеры и конфиг:** общий интерфейс, MIDI-вход, проигрыватель с виртуальным MIDI, Basic Pitch.
4. **Первые цифры:** MAESTRO + ASAP в режиме повтора → метрики тональности и нот.
5. **Лампа:** покупка и сборка 16×32, WLED, отрисовка кадра на Python → DDP. Волны от оси и фон тональности.
6. **Комната:** re-amping через Shure, замеры задержки и RTF.
7. **Видео + одностраничник + репозиторий → письмо** первому автору статьи JKU (Patricia Hu) с вопросом о коде Causal-AMT и возможности Project Practical.

## Коммерческая версия

Продукт — лампа, которая работает сама, плюс приложение как режим «про»; исследовательская и коммерческая версии могут опираться на разные модели.

**Режимы**

| Режим                    | Источник          | Анализ                                                                                                   | Где считается |
| ------------------------ | ----------------- | -------------------------------------------------------------------------------------------------------- | ------------- |
| Музыка в комнате (треки) | микрофон лампы    | тональность + онсеты + доли; без нот                                                                     | ESP32-S3      |
| Живое фортепиано         | телефон у пианино | + транскрипция; калибровка усиления и строя (`estimate_tuning`)                                          | смартфон      |
| Цифровое пианино         | Bluetooth MIDI    | ноты без ошибок                                                                                          | смартфон      |
| Свой файл в приложении   | файл напрямую     | тяжёлые модели «вперёд», предвосхищение модуляций, компенсация задержки вывода (`outputLatency`, AAudio) | смартфон      |

Стриминги нельзя захватить напрямую (iOS — запрет, Android — приложения отключают захват), поэтому для них только микрофон. Компьютер может брать звук системы (PipeWire monitor, WASAPI loopback).

**Смартфон**

- Мощности хватает: Core ML, LiteRT/NNAPI, ONNX Runtime Mobile, int8; пример мобильной транскрипции — Mobile-AMT.
- Отключить системную обработку звука: iOS — режим `.measurement`, Android — источник `UNPROCESSED` + Oboe.
- Ограничения: фоновая работа на iOS, нагрев и батарея, разрешение на локальную сеть.

**Связь телефон → лампа:** передавать состояние (~100 байт × 30/с), лампа рисует сама. Bluetooth LE вместо Wi-Fi: ~3 КБ/с, без настройки сети, интервал соединения 7,5–30 мс.

**Выбор модели по жанру и инструменту:** YAMNet (AudioSet, 521 класс: инструменты и жанры) раз в несколько секунд. Влияет на слой нот (фортепиано → фортепианная модель, гитара → Basic Pitch, оркестр → слой выключен) и параметры тональности. Гистерезис 5–10 с; начать с ручного выбора режима.

## Идеи на будущее

- **Тренажёр гармонического слуха.** Режимы «угадай → проверь», отложенная подсказка (цвет через 1–2 с), угасающая поддержка (α уменьшается с правильными ответами). Прогрессия: T–S–D в мажоре → в миноре → ii, vi → побочные доминанты → модуляции. С MIDI — «играю и вижу». Архитектура уже поддерживает: это задержка и сила α в отрисовке.
- **Исследование восприятия:** ускоряет ли цветовая обратная связь развитие функционального слуха (две группы, несколько недель, тест до и после; нужны участники и этическое согласование). Кандидат в бакалаврскую работу.
- **Сравнение с партией света Скрябина** в «Прометее» (_Luce_, разбор Gawboy и Townsend).
- **Дообучение модели** на комнатных записях с Shure против исходной.
- **Маленькая модель транскрипции для ESP32-S3** (CQT → 88 активаций, 100–300 тыс. параметров, int8, MAESTRO): компромисс размера и точности.
- **Физическая ось:** центральная LED-лента внутри полупрозрачной оболочки.
